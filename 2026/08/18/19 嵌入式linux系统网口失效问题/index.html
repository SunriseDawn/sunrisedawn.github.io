2 关于/etc/network/interfaces

本身是一个配置文件，系统是通过读取这个文件的内容，来知道应该如何配置网络接口的

核心执行者：ifupdown 工具集

在 Debian 及其衍生系统（如 Ubuntu）中，传统的网络配置方式就是通过 ifupdown 工具集来完成的。

  • 核心命令：ifup 和 ifdown。ifup 命令会读取 /etc/network/interfaces 文件，然后根据文件中的定义来启用（bring up）一个网络接口；ifdown 则相反，用于禁用（bring down）一个接口。
  • 工作原理：ifupdown 是一个“高层工具”，它本身不直接操作硬件，而是调用 iproute2 等底层工具并通过内核 API 来最终完成 IP 地址配置、路由设置等任务。

3 该系统启动流程

① Boot ROM（芯片固化，不可改）

  • CPU 上电后执行芯片内部 ROM 里的代码
  • 初始化最小硬件（时钟、DDR 控制器等）
  • 从预设介质加载 bootloader：eMMC、SD、NAND、SPI NOR…
  • 易错点：介质没烧录/烧错位置 → 卡死在 ROM 阶段（无任何输出或只有 ROM 打印）

② Bootloader（U-Boot）

任务：初始化硬件 → 加载内核和设备树 → 跳转执行

③ Linux Kernel

任务：解压自解压内核 → 初始化子系统 → 挂载根文件系统 → 执行 init

关键点：

  • root= 参数决定挂哪个分区；rootwait 表示等设备出现
  • 挂载根后，内核查找并执行 /sbin/init（除非命令行指定了 init= 或 rdinit=）
  • 易错点
    • Kernel panic - not syncing: VFS: Unable to mount root fs → root 设备不存在/文件系统错
    • No working init found → /sbin/init 不存在

  • 易错点：switch_root 没写/写错 → 停在 initramfs，你真实的 /etc 永远不会被执行
  • 判断方法：启动后 cat /proc/mounts | head，如果根是 rootfs 而不是 /dev/xxx，说明没切过去
