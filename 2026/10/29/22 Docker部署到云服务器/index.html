4 运维

4.1 docker 配置变更怎么办

机制：**编排文件在 git 里 → 服务器 git pull → remote-infra.sh up**。

up -d 只会重建「配置变了」的容器，没变的不动，数据在命名卷里不受影响。

变更类型 操作 数据影响
改参数（堆内存、mem_limit） 改 deploy/.env.remote 或 compose → push → 服务器 git pull && bash scripts/remote-infra.sh up 不受影响
加新中间件（如 MinIO） 同上，新增一个 service 新卷，空的
改镜像小版本（16.1→16.3） 同上 不受影响
改镜像大版本（PG 16→17） ⚠️ 数据目录不兼容：先 backup → 改 tag → up → 从 dump 恢复 需迁移，不能直接改
改密码 改 compose 不生效（首次初始化已写进卷），要进容器 ALTER USER 或清卷重建 —
删中间件 up 后加 --remove-orphans，卷会留着（要彻底删再 docker volume rm） 卷残留

4.4 排障速查

现象 先查什么
服务报 Unable to determine Dialect 数据库通不通 → 进程里 PG_HOST 的值 → 库名账号
Kafka 报 Connection to node -1 (localhost...) KAFKA_ADVERTISED_HOST 是不是还是 127.0.0.1
容器起不来 bash scripts/remote-infra.sh logs <服务名>，看最后 20 行
端口冲突 bash scripts/remote-infra.sh doctor
本机连不上 ss -tlnp | grep 5432 看服务器绑的是不是 192.168.2.90
页面能开但没数据 先确认 4 个 Java 服务都起来了（netstat | grep -E ":(9001|8081|8800|9002) "）
